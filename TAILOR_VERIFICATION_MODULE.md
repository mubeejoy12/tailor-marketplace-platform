# Tailor Verification Module

## Overview

The Tailor Verification System allows tailors to submit identity documents for admin review, earn a Verified badge, and qualify for Premium status. It creates a trust layer between customers and tailors on the marketplace.

---

## Architecture

```
Tailor (browser)
    │
    ▼  POST /api/tailors/verification-request
VerificationController.java
    │
    ▼
VerificationService.java         ← business logic
    │
    ├── VerificationRequestRepository  ← audit trail
    ├── TailorProfileRepository        ← update verified/premium/status
    └── NotificationService            ← notify tailor of outcome

Admin (browser)
    │
    ▼  GET/PUT /api/admin/verifications/...
VerificationController.java
    │
    ▼
VerificationService.approve() / .reject()
    │
    └── TailorProfile.verified = true / false
        TailorProfile.premium  = (verified ∧ orders≥20 ∧ rating≥4.5)
```

## Database Schema

### verification_requests table

```sql
CREATE TABLE verification_requests (
    id                BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    tailor_id         BIGINT        NOT NULL,
    national_id_number VARCHAR(255) NOT NULL,
    id_document_url   VARCHAR(255) NOT NULL,
    selfie_url        VARCHAR(255),
    status            VARCHAR(50)  NOT NULL DEFAULT 'PENDING',
    submitted_at      TIMESTAMP    NOT NULL DEFAULT now(),
    reviewed_at       TIMESTAMP,
    review_note       TEXT,
    CONSTRAINT fk_verreq_tailor FOREIGN KEY (tailor_id) REFERENCES tailors(id)
);

CREATE INDEX idx_verreq_tailor_id ON verification_requests (tailor_id);
CREATE INDEX idx_verreq_status    ON verification_requests (status);
CREATE INDEX idx_verreq_submitted ON verification_requests (submitted_at);
```

### tailors table — new columns

```sql
ALTER TABLE tailors ADD COLUMN verified         BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE tailors ADD COLUMN premium          BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE tailors ADD COLUMN completed_orders INT     NOT NULL DEFAULT 0;
ALTER TABLE tailors ADD COLUMN total_reviews    INT     NOT NULL DEFAULT 0;
```

## Lifecycle States

```
UNVERIFIED  ──(tailor submits)──▶  PENDING
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                       APPROVED               REJECTED
                          │                       │
               verified=true, badge       tailor may resubmit
               premium check runs
```

## Premium Status Rules

A tailor becomes **Premium** automatically when all three conditions are met:

| Condition | Threshold |
|-----------|-----------|
| Identity verified | `verified = true` |
| Completed orders | `completedOrders >= 20` |
| Average rating | `rating >= 4.5` |

Premium is recalculated:
- When admin approves a verification
- When an order reaches DELIVERED status
- When a review is submitted

---

## Business Rules

| Rule | Enforcement |
|------|-------------|
| Only tailors can submit requests | Frontend guard (TAILOR role check) |
| Only one PENDING request at a time | `existsByTailorIdAndStatus(tailorId, "PENDING")` check |
| Cannot resubmit when already APPROVED | `verified=true` guard in `submitRequest()` |
| Only PENDING requests can be acted on | `assertPending()` check in approve/reject |
| Admin note required for rejection | Frontend validation (UX) |
| Premium auto-updates | `checkAndSetPremium()` called from OrderService + ReviewService |

## Frontend Pages

| Page | Path | Role |
|------|------|------|
| Tailor Verification | `/verification` | TAILOR |
| Admin Review Panel | `/admin/verifications` | ADMIN |

### `/verification` states

- **UNVERIFIED / REJECTED** → submission form (nationalIdNumber, idDocumentUrl, selfieUrl)
- **PENDING** → waiting card with submission timestamp
- **APPROVED** → celebration card with verified + premium badges
- All states show Premium eligibility progress bar

### `/admin/verifications` features

- Tab filter: All / Pending / Approved / Rejected
- Expandable cards showing all submitted documents with direct links
- Inline approve/reject with note field
- Optimistic UI update on action
